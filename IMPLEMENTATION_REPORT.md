# Resilio implementation report

The existing native SwiftUI project was revised in place. The original bundle identifier, local filenames, environmental provider, profile compatibility decoder, and time-weighted exposure calculations remain.

## Change inventory

1. **Screens changed:** onboarding, Home, Schedule, exposure results, Calendar/event details, Profile/editor, and local planning assistant. Added Settings and a reusable location chooser. Resilio display name, provided logo, app icon, sage/forest palette, adaptive gray surfaces, large tap targets, and source disclosures are connected to real state.
2. **Components created:** Resilio theme/brand and primary button style, condition/event cards, eager month grid with event dots, location picker and explicit search results, settings/connections, EventKit service/export editor, shared forecast repository, route/account/calendar service boundaries, local assistant parser, testable tag rules, and regression runner.
3. **Components removed/replaced:** no About page or duration-shortening control existed in this checkout. Replaced the old graphically selected date with a month overview, placeholder calendar permission button with EventKit connections, broken profile switch button, demo-specific AI extraction, arbitrary hourly particle categories, invalid temperature-percentage comparisons, and stale-only event details. Removed the unused DraftSummary and old PM2.5-band helper. Existing useful exposure and profile models were extended rather than duplicated.
4. **Navigation:** exactly Home / Schedule / Calendar / Profile. AI opens a sheet and sends its draft into Schedule. Home event selection switches to Calendar and opens the matching event. Results save/update routes to that event. Profile hosts settings/privacy.
5. **Profiles:** optional age (0–120), home ZIP validation, voluntary health tags/custom entries, case-insensitive duplicates, 25 per field, active-profile persistence, sample-profile reuse fix, and working create/edit/switch/delete. Deletion asks about removal of that profile's Resilio plans. Existing events retain their profile IDs when active profile changes. Protected JSON writes report errors and refuse to overwrite unreadable data.
6. **Events:** original ActivityPlan is preserved separately from selectedStart. Re-analysis uses the same event ID and keeps original baseline/creation date. Address coordinates/time zone, flexibility, optional route, and environmental snapshot/provenance persist; health lists are never duplicated into events. Explicit offline save is labeled as unanalyzed.
7. **Calendar:** month navigation, selected day, dots, upcoming plans, event details, edit/delete, forecast refresh on open, and re-analysis. Apple events are a separate read-only source display. Planning around one creates a separate Resilio plan. Exported copies do not sync automatically.
8. **Environmental behavior:** real Open-Meteo weather and air-quality data; provider US AQI categories on Home, simple particle/heat values for plans. Checks roughly every minute while Home is active, 15-minute shared source cache, coalesced requests, preserved last successful forecast on refresh failure, and separate app-check/retrieval labels. Provider source-update time is explicitly unavailable. No invented environmental results or route reductions. Comparisons require complete PM2.5 coverage and at least 10% modeled reduction, not a clinical significance claim. Duration is fixed and past/out-of-window alternatives are excluded.
9. **Google Maps:** unconfigured. Apple MapKit search/geocoding works now, including a fallback when autocomplete is unavailable. An HTTPS adapter and route selection UI are ready for a Google Routes backend, but no backend/credentials were supplied. No claim that Google is working.
10. **External calendars:** Apple EventKit read and native editor export implemented. Google Calendar and Outlook OAuth/sync are not implemented and display Setup required. Device calendars already visible through Apple Calendar retain their calendar names. No fake connections.
11. **AI:** existing local functionality preserved and generalized; no hosted model configured. The interface explicitly says it is a local parser. It extracts simple profile/activity/date/time/duration details, flags missing or ambiguous data, and routes to the shared Schedule/exposure workflow. It is not a general conversational language model.
12. **Mocks:** the opt-in Maya demo profile is synthetic and labeled. Regression fixtures are synthetic and only exist in Tests. No hardcoded environmental values, routes, exposure improvements, or connected-service states appear in the app.
13. **Configuration:** Google Routes backend/credentials, Google and Microsoft OAuth registrations, account authentication, and hosted AI remain external setup/implementation tasks. No secrets were added to the client. See INTEGRATIONS.md.
14. **Limitations:** forecasts cover a short provider window; longer-range events can be saved without analysis and checked later. Public forecast grids cannot distinguish neighboring-route exposure. Local assistant handles simple language and asks users to review fields, including AM/PM ambiguity. Apple import/export is implemented but live account synchronization and every permission branch still need device testing. No push notifications, background minute polling, Apple Health, health-record access, or two-way sync. Production legal/operator details and service configuration remain to be finalized.

## Exact demo flow

1. Run Resilio. Choose **Continue on this device** (hosted account sign-in is not configured).
2. Choose **Enter a location** and search/select a place, or skip location. The Maya demo's home ZIP can also supply Home conditions.
3. Read the terms/privacy screens, select both agreement toggles, continue through optional-data information, and choose **Try Maya, a demo profile**. Tap **Start planning**.
4. Home should show live forecasts or a clear retrieval error; open Forecast details to see distinct check/retrieval times. No sample environmental readings are substituted.
5. Open Schedule. Choose Maya, enter **Soccer Practice**, and search **Roosevelt Island New York soccer field**. Select **Firefighters Field, 405 Main St New York NY 10044** or another actual result. Review the address.
6. Choose a future start within the next two days, duration **90 min**, and **Up to 1 hour earlier or later**. Tap **See Exposure**.
7. Keep the original or select an actual returned lower-exposure option. At most five alternatives appear. If none qualify, the explicit no-improvement message is expected. Tap **Save Event**.
8. Close event details to view the Calendar month dot and event. Open Home, scroll to Upcoming plans, and tap it: Calendar opens the same event. Use **Check alternatives again**, then **Update Event**; no duplicate should appear.
9. Use **Edit plan** to change its name/time/address, review exposure, and update. Create another profile with health fields left empty, switch to it, and verify new plans default to it while Maya's saved event still belongs to Maya.
10. Schedule a **Doctor Appointment** with **No, the time is fixed**. Analysis must not suggest another appointment time. Routes remain Setup required without a configured backend.
11. Home → **Plan with AI**: enter **Maya has soccer practice tomorrow at 6 pm for an hour and a half.** Review the extracted draft in Schedule, select an exact address and flexibility, and use the same exposure flow. Try **at 6** without AM/PM to see the review reminder.
12. Profile → Settings: change units, change manual location, review privacy/service status. Calendar → Connect Apple only if you want device events shown. Event details → Add a copy to Apple Calendar opens Apple's editor; cancel or explicitly save there. Google/Outlook remain clearly unconfigured.
